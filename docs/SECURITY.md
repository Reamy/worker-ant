# 工蚁系统安全策略

> 适用形态（2026-10-24）：Electron 桌面端（引擎运行在 main 进程内）+ ANS（`:27183`）。
> 本文明确安全边界、威胁模型与各层防护的**真实局限**；不含已归档形态（Docker 三容器、JWT RBAC、IM webhook 端点）。

## 安全哲学

**进程内检查是启发式的，不是承载安全的边界。** 注入检测、命令意图分类、YOLO 分类器都只能**抬高**攻击成本，
不能保证 100% 防御。真正的安全边界是**操作系统层的隔离**：文件系统权限、网络隔离、专用账户 / 容器。
工蚁默认以**你自己的用户身份**在你的机器上执行——它信任你，但它不能替你决定你信任谁。

## 威胁模型

| 威胁向量               | 风险 | 缓解措施                                                                              |
| ---------------------- | ---- | ------------------------------------------------------------------------------------- |
| 提示注入（用户输入）   | 高   | `<user_content>` 标签包裹、注入模式检测、Unicode 走私清理；**启发式，不是边界**       |
| 工具滥用（Agent 调用） | 高   | 权限分级（`normal` / `privileged`，后者需 `ask_user` 审批）、命令意图分类、无进展检测 |
| 越界读写 / 命令        | 高   | 沙箱三层：路径围栏 + 命令意图分类 + 模式判决（`strict` / `workspace` / `off`）        |
| 敏感信息泄露           | 中   | PII 检测遮蔽、危险代码模式检测、输出安全检查                                          |
| 记忆投毒               | 中   | 记忆写入威胁扫描、去重合并、过期淘汰                                                  |
| 供应链攻击（MCP/A2A）  | 低   | ANS 注册中心审批制、HMAC 签名验证                                                     |
| DoS（资源耗尽）        | 中   | 成本 / token 预算、步数上限、子 Agent 超时、无进展暂停                                |
| 本地许可被绕过         | 中   | 档位闸 + 设备指纹 + 签发口径；**只能抬高成本，锁不死**（源码在明处）                  |

## 安全层级

```
第一层：输入护栏（injection detection + unicode sanitization + user_content wrapping）
第二层：工具门控（权限分级 + 命令意图分类 + 路径围栏 + 无进展检测 + 每步真停）
第三层：输出护栏（PII masking + dangerous code detection + cost / token budget）
第四层：进程边界（桌面↔ANS 出站 HMAC-SHA256 + AES-256-GCM 密钥字段 + 全量参数化查询）
```

- **桌面 ↔ ANS**：每次请求带 `X-Api-Key` / `X-Timestamp` / `X-Signature`，时间戳窗口外拒绝。
  ANS 侧的资源管理、网关、计费、节点、团队、权益接口均需 HMAC 验签。
- **密钥存储**：环境变量或 DB settings；敏感字段 AES-256-GCM 加密。
- **SQL**：better-sqlite3 全量参数化查询。
- **工具执行**：越界即拒；`strict` / `workspace` 沙箱把工具操作限制在工作目录内；
  Agent 的每一步都可暂停、中断、追加输入，**暂停即真停**。
- **设备控制**：「看见不等于授权」——原始控制须显式勾选，不以"已发现设备"推断"已获准控制"。

## 已知局限性

1. **进程内检查非沙箱**：注入检测、命令意图分类、YOLO 分类器等均为启发式规则，可能遗漏复杂攻击模式。
   如果你要让 Agent 处理**不可信内容或不可信代码**，请自行把它放进操作系统级隔离
   （专用账户、只读挂载、容器 / 虚拟机、网络隔离）。仓库**不再随附 Docker 部署**，隔离方案由你按需搭建。
2. **LLM 安全分类器为启发式**：基于工具名 + 调用历史的规则评分，不是完整的 LLM side-query。
3. **Token 估算为近似值**：按字符类型估算（ASCII 约 4 字符/token，CJK 约 1.5 字符/token），非精确 tiktoken 计数。
4. **IM 入站在桌面端不依赖公网回调**：飞书 / 钉钉 / QQ 走**出站长连接**，企业微信**仅出站**。
   入站消息仍属**不可信输入**，会经过同一套输入护栏；不要把"连接是出站的"误当成"内容是可信的"。
5. **文件系统安全依赖 OS**：工具结果与产出物落在 `data/task_outputs/`、项目工作目录，默认**不加密**。
   敏感环境请使用全盘加密与受限账户。
6. **本地许可闸可被绕过**：源码在明处，本地闸只抬高成本。真正能挡的是联网才给得出的能力与云端权益。
7. **自动登录是有意的便利边界**：仅当库中仍是「唯一一个、尚未改密的默认管理员」时生效；
   设置新密码或新增第二人后即永久失效。请在开始真实使用前修改默认密码。

请通过 GitHub Issues 报告安全漏洞。勿在公开渠道披露可利用细节。

## 定期审查

- 每季度审查依赖安全（`pnpm audit`）
- 每次发布前运行 `security_audit` 技能检查
- 对处理不可信输入的部署，定期做隔离边界复核
