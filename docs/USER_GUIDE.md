## 概述

工蚁是一个跑在你自己机器上的 AI 执行平台。你用自然语言派活，它在**本机**改文件、跑命令、提交 git，
把产出登记成可交付资产；你出门在外，用微信 / 钉钉 / 飞书发条消息就能查进度、审产物。

系统只有两部分：

| 组成               | 说明                                                                    |
| ------------------ | ----------------------------------------------------------------------- |
| 桌面端（Electron） | 引擎本体：项目/任务引擎、调度器、Agent 执行循环、记忆、IM、成果交付     |
| ANS（AI 资源中心） | 唯一常驻 HTTP 服务，默认 `:27183`；模型匹配 / Gateway / 计费 / 技能同步 |

桌面端经 `ans-client`（出站 HMAC 签名）调用 ANS；桌面端本身**不暴露 HTTP API**。

## 安装与启动

### 方式一：安装包（macOS）

从 [GitHub Releases v0.2.2](https://github.com/Reamy/worker-ant/releases/tag/v0.2.2) 下载
`worker-ant-0.2.2-mac-arm64.dmg`（或 `.zip`），挂载后把「工蚁」拖进「应用程序」。
**v0.2.0 安装包首次启动会报 `ENOENT mkdir '/data'` 并崩溃，请勿使用。**
v0.2.2 修复了退出后残留 ANS 进程、首次启动未进入安装向导两个问题；自动更新尚未启用，已装 v0.2.1 的用户请手动下载覆盖安装。

- 系统要求：**macOS 13+，Apple Silicon（arm64）**。暂不提供 Intel Mac 与 Windows 版本。
- 安装包已完成 Developer ID 签名并经 Apple 公证，首次打开无需右键绕过。
- 首次启动进入**安装向导**，四步跑出第一个成果（见下节）。

### 方式二：从源码运行

环境要求：Node.js ≥ 22.21.1、pnpm ≥ 9。

```bash
pnpm install

# 终端 1 —— 启动 ANS（:27183）。必须先起：
#   它会把共享的 better-sqlite3 重建为 Node ABI
pnpm dev:ans

# 终端 2 —— 启动桌面端（请在 macOS Terminal.app 中运行，勿用 IDE 终端）
cd apps/worker-ant-desktop && bash run.sh
```

> 两条 ABI 互斥：`run.sh` / `desktop:dev` 会把共享的 `better-sqlite3` 重编为 Electron ABI，
> 而 ANS 需要 Node ABI。故源码态下**必须先跑 `pnpm dev:ans`**；桌面端的「按需代起」在 dev 下会如实失败并提示。
> 打包版不受影响：ANS 运行时随包在 `Resources/ans-server/`，以 `ELECTRON_RUN_AS_NODE=1` 代起。

端口默认 `27183`，可用环境变量 `ANS_SERVER_PORT` 覆盖。

## 首次启动与安装向导

干净机器上，向导四步（`#/onboarding`）：

| 步骤             | 做什么                                                            |
| ---------------- | ----------------------------------------------------------------- |
| ① 连接模型       | 填 ANS 地址与凭据（或把你的 OpenAI 兼容端点接进 ANS）；保存并自检 |
| ② ANS 自检       | 检查可达性、模型目录、是否有可用 chat / embedding 模型            |
| ③ 选 / 建项目    | 选一个已有项目，或新建第一个项目                                  |
| ④ 跑出第一个成果 | 选一个开箱模板建任务，工蚁自动拆解并执行                          |

- 自检未通过**仍可继续**，但界面会如实标注「可能跑不出结果」——不假装通过。
- 若当前没有可用 chat 模型，任务能创建但会如实记 `no_model`，不会编造结果。
- 向导可以稍后从「系统设置 → 示例项目」附近重新进入；左侧导航里也有一条首启导览（依次高亮核心入口）。

## 登录与认证

### 本机所有者自动登录

首次启动会自动创建唯一的管理员并**免登录**直达安装向导：

- 邮箱：`admin@worker-ant.local`
- 密码：`admin123`（兜底登录用）
- 角色：`super_admin`

只要库里仍是「**唯一一个、尚未改密的默认管理员**」，桌面端每次启动都会自动以本机所有者身份登录。
自动登录会在任一条件成立后**永久失效**，届时需用邮箱 + 密码登录：

- 你设置了新密码（或改过密码）；
- 库里出现了第二个人（邀请 / 创建了其他账号）。

安装向导顶部与「系统设置」页各有一张「设置本机密码」卡片。设置新密码后本机没有找回入口，请记牢；
需要兜底时仍可用上表默认密码登录。**生产使用请立即修改默认密码。**

### 登录方式

- **邮箱 + 密码**：`/login`。
- **OAuth**：桌面端支持经系统浏览器 + `worker-ant://` 自定义协议完成（需自行配置对应 OAuth 凭据）。

### 角色

| 角色          | 权限                       |

| `super_admin` | 全部权限，包括修改用户角色 |
| `admin`       | 管理项目、任务、资源       |

### 项目状态

`active`（运行中）、`paused`（已暂停）、`completed`（已完成）、`archived`（已归档）。
状态流转经项目详情页操作；已归档项目为只读。

### 项目视图

项目详情页汇总：任务树、产出物、项目记忆、知识卡片、运行指标与健康评分。
克隆项目会复制任务结构（任务状态重置为 `pending`）。

## 任务管理

### 新建任务（`/tasks`）

| 字段             | 说明                                   |
| ---------------- | -------------------------------------- |
| 任务模板         | 从内置 / 自建模板起步                  |
| 标题 / 描述      | 描述支持 Markdown                      |
| 优先级           | `0` 普通、`1` 优先、`2` 紧急、`3` 最高 |
| 验收标准         | 完成判据；未通过会被压分并如实记录     |
| 父任务（可选）   | 设为子任务                             |
| 关联方案（规划） | 关联规划文档                           |
| 附件（可选）     | 支持拖放；随任务上下文交给 Agent       |

### 任务状态（取值域 11 个）

| 状态            | 界面文字   | 说明                                     |
| --------------- | ---------- | ---------------------------------------- |
| `pending`       | 待执行     | 已入队，等调度器认领                     |
| `planning`      | 规划中     | Agent 正在拆解计划                       |
| `preparing`     | 准备中     | 正在准备上下文（恢复中也经过此态）       |
| `executing`     | 执行中     | 正在执行工具调用                         |
| `running`       | 运行中     | 执行中的另一写入态（调度器认领后）       |
| `paused`        | 已暂停     | 暂停等待输入或人工确认，可恢复           |
| `investigating` | 调查中     | 执行异常后的诊断态                       |
| `stabilizing`   | 稳定观察中 | 短时间反复改状态，引擎主动停手等人工确认 |
| `completed`     | 已完成     | 终态                                     |
| `failed`        | 失败       | 终态；可恢复或重试                       |
| `archived`      | 已归档     | 任务被放弃（与项目归档同词不同域）       |

### 任务操作

- **执行**：`pending` → 入队执行。
- **暂停**：立即中止在途执行，保留对话，可恢复。
- **中止**：同暂停，但语义是强中断；保留产出。
- **恢复**：`paused` / `failed` 保留对话继续；**重试**则清空对话从零开始。
- **追加输入**：执行中注入提示，任务带新输入继续。
- **标记完成 / 删除 / 编辑**：按当前状态可用。
- `stabilizing` 不会自动超时，需在详情页点「确认并放回队列」给出明确出口。

### 执行可见性

详情页实时显示：当前步骤、工具调用、token 消耗与预算水位、上下文占用估算、预估剩余步数。
每一步都写事件（`wa_event_log`），可暂停 / 恢复 / 重放 / 审计。

## 产出物

`/deliverables` 汇总所有任务交付的成果（文件、文档、代码变更等）。

- 产出物登记为一等公民：有类型、来源任务、版本与验收结果。
- 详情抽屉可翻开文件、查看来源任务与验收评分。
- 已被后续变更覆盖、或文件已失效的产出物，会标记状态（如 `stale` / `retired`），不冒充现役。

## 记忆

`/memories` 是系统记忆（跨项目）；项目记忆在项目详情页。四类记忆：

- **情景**（episodic）——发生过什么；
- **语义**（semantic）——事实与知识；
- **程序**（procedural）——怎么做；
- **反省**（retrospective）——做完之后的教训。

记忆支持检索、编辑、合并与过期淘汰；前瞻记忆到期会在界面浮出提醒。项目知识包（导出 / 导入）与领域包属 **Pro** 能力。

## IM 渠道

### 支持平台与能力边界

| 平台       | 类型标识          | 入站 | 出站 | 说明                                           |
| ---------- | ----------------- | ---- | ---- | ---------------------------------------------- |
| 微信个人号 | `wechat-personal` | ✅   | ✅   | iLink 长轮询 + 扫码登录                        |
| QQ         | `qqbot`           | ✅   | ✅   | 开放平台 Gateway WebSocket 长连接（免公网 IP） |
| 飞书       | `feishu`          | ✅   | ✅   | WebSocket 长连接（需在开放平台开启长连接）     |
| 钉钉       | `dingtalk`        | ✅   | ✅   | Stream 长连接模式（免公网 IP）                 |
| 企业微信   | `wecom`           | ❌   | ✅   | **仅出站**：通知能到达，用户回复不会进入引擎   |

> 企业微信没有原生 WebSocket / 长轮询，桌面端也不提供公网回调服务，因此入站未实现。
> 渠道列表会给它标一个「仅出站」徽标，不把单向说成双向。

### 添加与启动渠道（`/im`）

1. 进入「IM渠道」页面，点「添加渠道」。
2. 选择渠道类型，按 `docs/im-config-guide.md` 填写凭证（字段名与页面一致）。
3. 保存后点「启动」：微信显示二维码供扫码；其余平台按配置建立长连接。
4. 「诊断」检查配置完整性、连通性与连接状态。

### 入站媒体

图片 / 文件 / 语音等非文本消息会以类型占位符出现在对话里（如 `[图片]`、`[文件 report.pdf 1.2MB]`），
媒体落盘到 `data/attachments/<YYYYMMDD UTC>/<件名>`；同名追加 `-2` / `-3`，不覆盖。
这些消息止步于对话，不会被误建成任务。

### 消息流程

```
用户消息 → IM 适配器接收 → 意图识别 / 命令分发 → 建任务或恢复任务
→ Agent 引擎执行 → IM 回执 / 通知
```

## AI 资源管理

### AI 模型（`/models`）

- **供应商**：AI 服务提供商（名称 + API Base URL）。
- **模型**：模型 ID / 名称、能力标签（chat / embedding / vision / function-calling / image-generation / audio）、
  上下文窗口、最大输出、输入 / 输出价格（每千 tokens）。
- **端点**：每个模型可配多个端点（API URL、Key、优先级、权重），支持主备与负载均衡。
- **匹配策略**：最低成本 / 最低延迟 / 最佳能力 / 均衡；降级链路为首选 → 同供应商备选 → 跨供应商备选。

### 技能（`/skills`）

注册可被 Agent 调用的技能模块，内置 `code_review`、`security_check`；可从 ANS 同步。

### MCP 服务（`/mcp`）

Model Context Protocol 服务：名称、端点 URL、传输类型（stdio / streamable-http）、认证配置；
保存后自动探测工具清单。

### A2A 服务（`/a2a`）

Agent-to-Agent 协作：服务名称 + Agent Card URL。

### 插件市场（`/plugins`）

从 ANS 浏览并安装插件。

### API Keys（`/api-keys`）

用于外部服务以编程方式访问 ANS 网关：名称 + 资源组；密钥**仅创建时可见一次**，可随时吊销。
资源组限制该 Key 可访问的模型与能力范围。

## 数据目录与备份

- **dev**：仓库根 `data/`；**生产**：系统用户数据目录（`app.getPath('userData')`）。
- `data/worker-ant-server.db` —— 桌面工蚁主库（WAL）；`data/ans-server.db` —— ANS 库。
- 另有 `projects/ task_outputs/ notification_payloads/ attachments/ logs/ plugins/` 等子目录。

```bash
# 备份（服务空闲时复制即可）
cp data/ans-server.db data/backups/ans-$(date +%Y%m%d-%H%M).db
cp data/worker-ant-server.db data/backups/wa-$(date +%Y%m%d-%H%M).db

# 恢复
cp data/backups/ans-20260624-1200.db data/ans-server.db
cp data/backups/wa-20260624-1200.db data/worker-ant-server.db
```

> 跨仓库契约（勿破坏）：`NOTIFICATION_PAYLOAD_DIR=data/notification_payloads`（推送 `.txt` 落盘）；
> `data/cron_heartbeat.json`（cron 存活心跳，30 分钟阈值）。

## 安全边界

- **进程内检查是启发式的，不是安全边界**：注入检测、YOLO 分类器、危险代码模式等只能抬高攻击成本。
  真正的边界是**操作系统级隔离**（文件系统权限、网络隔离、专用账户 / 容器）。
- **桌面 ↔ ANS**：出站 HMAC-SHA256 签名 + 时间戳窗口。
- **密钥存储**：环境变量 / DB settings + AES-256-GCM 加密字段。
- **SQL**：全量参数化查询（better-sqlite3）。
- **工具执行**：权限分级 + 越界即拒 + 每步真停；沙箱可把操作限制在工作目录内。
- **设备控制**：「看见不等于授权」——原始控制须显式勾选。

详见 [`SECURITY.md`](SECURITY.md)。

## 常见问题

**Q：启动后模型不可用 / 任务记 `no_model`？**
先确认 ANS 已起（`lsof -iTCP:27183`），再到 `/models` 确认至少有一个可用 chat 模型且有端点与 Key。

**Q：源码态下桌面端提示「请先运行 pnpm dev:ans」？**
正常。`run.sh` 把 `better-sqlite3` 重编为 Electron ABI，ANS 需要 Node ABI；先起终端 1 再起终端 2。

**Q：安装向导能跳过吗？**
可以。向导是引导，不自检通过也能继续；之后可在「系统设置」重新进入。

**Q：改过密码后每次都要登录？**
是。自动登录只在「唯一一个、尚未改密的默认管理员」时成立；这是有意的安全边界。

**Q：企业微信为什么收不到我的回复？**
企业微信渠道在桌面端**仅出站**：无原生长连接、无公网回调。要双向对话请用微信 / QQ / 飞书 / 钉钉。

**Q：数据存在哪？怎么迁移？**
见「数据目录与备份」。开发态在仓库 `data/`，生产在系统用户数据目录；复制两个 `.db` 文件即可迁移。

**Q：Intel Mac / Windows 能用吗？**
当前只提供 macOS arm64（macOS 13+）。
